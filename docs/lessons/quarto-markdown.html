Отчёты в Quarto: формат QMD

Как устроен .qmd-файл: текст, код R и готовый документ

Что такое .qmd

В обычном скрипте сохраняется код, но его результаты обычно остаются в текущей сессии R: числа – в консоли, графики – на панели Plots и т. д. Чтобы отправить куда-то свои результаты, пришлось бы вручную копировать их, а если код будет исправлен, то нужно будет повторять эту работу…

Quarto Markdown – формат текстовых файлов с расширением .qmd. В нём удобно писать отчёты с расчётами, таблицами, графиками и пояснениями к ним – он хранит текст, код R и настройки оформления. Quarto собирает из файла отчёт: оформляет текст, выполняет код и сохраняет результат его работы. Из .qmd можно получить HTML-страницу для браузера, документ Word или PDF.

Файл .qmd – это исходник, который мы редактируем, а готовый HTML, Word или PDF – результат его сборки (Render). Если меняются данные или код, документ можно собрать заново, чтобы обновить результаты.

Как устроен файл

В типичном .qmd-файле чередуются обычный текст и чанки (chunks) – блоки выполняемого кода. В начале находится YAML-заголовок – настройки документа между двумя строками ---.

Вот небольшой файл целиком:

---
title: "Мой первый документ"
format:
  html:
    embed-resources: true
---

## Простой расчёт

Сложим два числа и получим **результат**.

```{r}
x = 2
y = 3
x + y
```

  1. title задаёт название документа

  2. Вложенная настройка format – формат результата (Отступ обозначает вложенность! в YAML для отступов используются пробелы).

  3. embed-resources: true помещает стили, изображения и другие ресурсы внутрь HTML, поэтому отчёт можно передать одним файлом. (Без этой настройки рядом с HTML может появиться папка с необходимыми ему ресурсами)

  4. Строка ## Простой расчёт становится заголовком раздела

  5. Двойные звёздочки **…** выделяют слово жирным.

  6. Запись {r} указывает, что внутри чанка находится код R.

После сборки под кодом появляется результат:

[1] 5

Текст и Markdown

Markdown – простая разметка текста: специальные символы обозначают заголовки, выделения, списки и ссылки.

В исходном файле В готовом документе
**важно** важно
*термин* термин
`x + y` x + y – код внутри текста, без выполнения
[сайт Quarto](https://quarto.org) сайт Quarto

Заголовки и пункты списка начинаются с новой строки:

## Раздел

### Подраздел

- Первый пункт
- Второй пункт

Чем больше символов #, тем глубже уровень заголовка. После # или - нужен пробел. Пустая строка отделяет один абзац от другого.

Напоминание

Внутри чанка R символ # начинает комментарий к коду.

Код R: запуск и сборка

Напомним, что в RStudio новый документ создаётся через File → New File → Quarto Document. Можно выбрать в открывшемся окне формат HTML и, например, назвать файл report.qmd.

В редакторе есть два режима; переключатель между ними находится над текстом документа:

  1. Source показывает исходную разметку.
  2. Visual позволяет оформлять текст в специальном редакторе с помощью меню.

Чанк начинается строкой с тремя обратными кавычками и {r}, а заканчивается строкой с тремя обратными кавычками. Кавычка здесь – знак `, а не апостроф '!

Новый чанк R можно вставить сочетанием Ctrl(Cmd) + Alt(Option) + I.

```{r}
a = 2
```

Зелёная кнопка запуска у чанка выполняет весь его код. Выполнять можно также построчно с помощью сочетания Ctrl(Cmd) + Enter. Результат появляется под чанком или в консоли.

Кнопка Render сверху собирает документ: заново выполняет все чанки сверху вниз и формирует файл выбранного формата. Собрать документ также можно сочетанием Ctrl(Cmd) + Shift + K. Для report.qmd с форматом HTML рядом появится report.html. Его можно открыть в браузере или отправить другому человеку.

Запуск отдельного чанка

Запуск отдельного чанка удобен для проверки расчёта, но сам по себе не обновляет готовый HTML-документ.

При сборке R-код выполняется в отдельной сессии. Объект, созданный в консоли, будет недоступен. Все нужные объекты должны создаваться в самом документе.

Например, чанк с x + y должен быть после кода x = 2 и y = 4.

Полезно выполнять Render регулярно: если в коде появилась ошибка, так проще найти место, после которого документ перестал собираться.

Настройки чанков

Можно отдельно управлять выполнением кода и тем, что читатель увидит в готовом документе. В Quarto настройки чанка записываются в его начале строками с #|:

```{r}
#| echo: false
2 + 3
```

Этот код выполняется, но в готовом документе виден только результат выполнения – [1] 5.

Настройка Что меняется при сборке
echo: false Код скрыт, результаты остаются
eval: false Код показан, но не выполняется
include: false Код выполняется, но и он сам, и весь его вывод скрыты
warning: false Предупреждения не выводятся в документ
message: false Служебные сообщения R не выводятся в документ

Предупреждение сообщает о возможной проблеме в вычислении, служебное сообщение – о ходе работы, например о подключении пакета.

Подробнее: Настройки выполнения, настройки для R.

Настройки для всего документа

Общие настройки выполнения помещаются в YAML-заголовок под ключом execute.

Например, этот заголовок создаёт автономный HTML-файл с оглавлением и скрывает код во всех чанках:

---
title: "Мой отчёт"
format:
  html:
    embed-resources: true
    toc: true
    toc-title: "Оглавление"
execute:
  echo: false
  warning: true
---

Настройка отдельного чанка имеет приоритет над общей.

Код стоит скрывать, когда читателю нужен только итог. Для совместной проверки анализа код полезно оставить видимым. Предупреждения также лучше не скрывать во время работы: они могут указывать на проблему в вычислениях.

Несколько приятных дополнений

Вычисление внутри текста.

Результат R можно вставить прямо в предложение. Сначала объект создаётся в обычном чанке:

```{r}
#| include: false
number_of_rows = nrow(iris)
```

Затем в исходном тексте можно написать:

Во встроенной таблице `iris` находится `r number_of_rows` строк.

После сборки получается: во встроенной таблице iris находится 150 строк.

Число обновится, если изменится код, который создаёт number_of_rows.

Можно было написать и просто: 
Во встроенной таблице `iris` находится `r nrow(iris)` строк.

Графики.

График появляется в отчёте, если код строит его внутри чанка.

Параметры fig-width и fig-height задают размеры в дюймах, fig-cap – подпись, а fig-alt – текстовое описание для доступности:

```{r}
#| fig-width: 7
#| fig-height: 4
#| fig-cap: "Распределение длины чашелистика ирисов"
#| fig-alt: "Гистограмма длины чашелистика со значениями примерно от 4 до 8 см"

hist(iris$Sepal.Length)
```

Размеры обычно подбирают после просмотра собранного документа.

Формулы.

Запись $E = mc^2$ превращается в \(E = mc^2\). Знаки доллара обозначают математическую разметку, а не вычисление в R. Разметка Markdown и формул.

Примечания.

Выделенный блок помогает вынести короткое уточнение:

::: {.callout-note title="Замечание"}
Здесь можно пояснить важную деталь.
:::
Замечание

Здесь можно пояснить важную деталь.

Это пример блока callout. Другие варианты примечаний.

Сворачиваемый код.

В HTML можно оставить результат видимым, а код спрятать под раскрывающейся кнопкой. Для этого в начале чанка задаются настройки:

#| code-fold: true
#| code-summary: "Показать расчёт"
Показать расчёт 
2 + 3
[1] 5

Кнопка выше раскрывает код этого расчёта. Оформление кода в HTML.

Другой формат.

Чтобы получить документ Word, в YAML можно заменить вложенный блок html строкой format: docx. Quarto создаст файл .docx. Ручные исправления внутри него будут потеряны при следующей сборке, поэтому содержание лучше менять в .qmd. Для PDF может потребоваться дополнительная система вёрстки LaTeX.

Типичные ошибки

Если документ не собирается, сообщение об ошибке обычно указывает, что нужно проверить:

  • объект не найден – объект создавался только в консоли либо нужный чанк расположен ниже. Перезапустите R через Session → Restart R и выполните чанки по порядку сверху вниз;
  • файл не найден – проверьте имя файла и относительный путь. При сборке путь по умолчанию отсчитывается от папки, где находится .qmd-файл;
  • ошибка YAML – проверьте двоеточия, отступы, обе строки --- и пустую строку после заголовка;
  • текст неожиданно стал кодом – проверьте, закрыт ли предыдущий чанк строкой с тремя обратными кавычками.
